# План: CLI-приложение "видео/аудио → транскрипт → выжимка"

## 1. Параметры проекта (зафиксировано по ответам)
- Интерфейс: CLI-утилита (Python).
- Транскрибация: локально, офлайн, через GPU (NVIDIA CUDA доступна — RTX 5060, 8GB VRAM).
- Суммаризация: локальная LLM через **Ollama**.
- Основной язык контента: русский.
- Вывод: только чистый текст транскрипта + текст выжимки (без таймкодов, диаризации, без batch-обработки папок — это сознательно вынесено за рамки MVP).

## 2. Пайплайн (общая схема)
```
[видео/аудио файл]
      │  (если видео) извлечь аудиодорожку
      ▼
  ffmpeg → WAV 16kHz mono
      ▼
  faster-whisper (GPU, CUDA) → сырой транскрипт (текст)
      ▼
  Ollama (локальная LLM) + промпт-шаблон → выжимка на русском
      ▼
  сохранение: <имя_файла>.transcript.txt
              <имя_файла>.summary.txt
```

## 3. Стек
| Компонент | Выбор | Почему |
|---|---|---|
| Язык | Python 3.11+ | лучшая экосистема под ML/аудио |
| CLI-фреймворк | Typer | минимум бойлерплейта, авто `--help`, типизация |
| Извлечение аудио | ffmpeg (через subprocess) | де-факто стандарт, нужен заранее установленным |
| Транскрибация | faster-whisper (CTranslate2, CUDA) | быстрее whisper.cpp/openai-whisper на GPU, меньше VRAM |
| Модель Whisper | `large-v3-turbo` (фоллбек `medium`, если не хватит VRAM) | хорошо распознаёт русский, ~1.5-2GB VRAM, быстрая |
| LLM-рантайм | Ollama (HTTP API на localhost:11434) | проще всего ставить/обновлять модели, готовый REST API |
| Модель для суммаризации | `qwen2.5:7b-instruct` (запасной вариант: `saiga`/`vikhr`-gguf модели, заточенные под русский) | сильная поддержка русского, ~5-6GB VRAM в Q4, влезает в 8GB вместе с системой |
| Логи/прогресс | rich / tqdm | удобный вывод в терминал |
| Упаковка | pyproject.toml, entry point `transcriber` | ставится через `pip install -e .`, вызывается как команда |

## 5. CLI-интерфейс (черновой)
```
transcriber process <путь_к_файлу> [опции]

Опции:
  --out-dir PATH        куда сохранить результаты (по умолчанию рядом с файлом)
  --whisper-model NAME  large-v3-turbo | medium | small ... (default: large-v3-turbo)
  --llm-model NAME      имя модели в Ollama (default: qwen2.5:7b-instruct)
  --lang CODE           ru (default) | auto
  --device cuda|cpu     (default: auto-detect, fallback cpu)
  --summary-style TEXT  краткая/подробная/тезисы (default: краткая)
  --keep-audio          не удалять промежуточный WAV
```
Плюс отдельные подкоманды `transcribe` и `summarize` для запуска только одного шага (полезно для отладки и повторного прогона выжимки без повторной транскрибации).

## 6. Этапы реализации
1. **M0 — Подготовка окружения** ✅ выполнено и проверено
   - Установлено через winget: Python 3.12.10, FFmpeg 9.0.2 (Gyan.FFmpeg), Ollama 0.40.4.
   - Venv (`.venv`) с torch==2.11.0+cu128, faster-whisper==1.2.1 (ctranslate2 4.8.3).
   - Модель `qwen2.5:7b-instruct` (4.8GB) скачана и протестирована через Ollama API.
   - **Проверено вживую**: PyTorch видит GPU (`RTX 5060`, compute capability `(12, 0)` = sm_120),
     faster-whisper на `device="cuda"` реально гоняет инференс на GPU, Ollama генерирует текст на
     русском через `qwen2.5:7b-instruct` на GPU (~77 ток/с).
   - **Найденные и решённые проблемы окружения (Windows + RTX 5060/Blackwell):**
     1. PyAV 19.x сломал сигнатуру `av.open()` (убрали `metadata_errors`), которую использует
        faster-whisper 1.2.1 → зафиксировали `av<19,>=18` в зависимостях.
     2. ctranslate2 (бэкенд faster-whisper) не находит `cublas64_12.dll` и часть
        `cudnn_*64_9.dll` — эти DLL есть в pip-пакетах `nvidia-cublas-cu12`/`nvidia-cudnn-cu12`,
        но лежат в чужой папке site-packages, и ни PATH, ни `os.add_dll_directory` не помогают
        нативному расширению ctranslate2 их найти. Рабочий фикс — копировать DLL прямо в папку
        пакета `ctranslate2` (Windows ищет зависимости рядом с загружаемым модулем):
        см. `scripts/fix_ctranslate2_cuda_dlls.py`. Нужно прогонять этот скрипт один раз после
        установки зависимостей (включить в будущий `localscribe doctor` / setup-инструкцию).
   - Осталось на будущее: оформить `localscribe doctor` — команду, которая на старте проверяет
     ffmpeg/CUDA/Ollama и подсказывает, что не так (сейчас всё проверено вручную).
2. **M1 — Извлечение аудио** ✅ выполнено
   - `src/localscribe/audio.py`: `extract_audio()` (видео/аудио → WAV 16kHz mono PCM через ffmpeg)
     и `temporary_audio()` (контекст-менеджер с авто-удалением временного файла).
   - Покрыто тестами (`tests/test_audio.py`, 8/8 passed): извлечение из аудио и из видео
     (видеопоток отбрасывается), кастомные sample_rate/channels, ошибки на отсутствующем
     и на битом файле, дефолтный временный выходной файл, очистка через `temporary_audio`
     (в т.ч. при исключении внутри `with`).
3. **M2 — Транскрибация** ✅ выполнено
   - `src/localscribe/transcribe.py`: `transcribe()` (аудио → `TranscriptionResult` с текстом,
     сегментами, языком, реально использованным устройством) и `save_transcript()`.
   - Автоматический fallback GPU → CPU при сбое инференса (не только при отсутствии CUDA,
     но и если реальный вызов на GPU упал во время работы) + авто-подбор `compute_type`
     (`int8` на CPU, т.к. `float16` там неэффективен/не поддерживается).
   - Проверено на синтезированной речи (Windows SAPI, голос Irina, `tests/fixtures/sample_ru.wav`) -
     текст распознан побуквенно точно, язык определён как `ru` с вероятностью 1.0.
   - 5 тестов в `tests/test_transcribe.py` (распознавание речи на GPU, явный CPU, отсутствующий
     файл, fallback GPU→CPU через monkeypatch, сохранение в файл).
   - **Важная находка (Windows): `torch` и `ctranslate2` в одном процессе конфликтуют по
     именам CUDA DLL** (оба грузят свою версию `cudnn_cnn64_9.dll`; кто первый импортирован -
     "занимает" имя в процессе, второй падает с `WinError 127`). Решение: `torch` не нужен
     в рантайме вообще - убрали его из зависимостей и из venv, проверка GPU теперь через
     `ctranslate2.get_cuda_device_count()` (без каких-либо конфликтов).
4. **M3 — Суммаризация** ✅ выполнено
   - `src/localscribe/summarize.py`: `summarize()` → `SummaryResult`, `save_summary()`,
     `check_ollama_available()`, `list_ollama_models()`.
   - 3 стиля выжимки (`краткая` / `подробная` / `тезисы`), промпты на русском.
   - Map-reduce для длинных транскриптов: текст режется по границам предложений на части
     ≤`SUMMARY_CHUNK_CHAR_LIMIT` символов, каждая часть суммаризируется отдельно ("map"),
     затем промежуточные выжимки сводятся в одну финальную ("reduce").
   - 12 тестов (`tests/test_summarize.py`): реальные вызовы Ollama (краткая/тезисы/map-reduce)
     + мокнутые ошибочные пути (сервер недоступен, HTTP-ошибка), чанкинг, сохранение в файл.
   - **Доработка после реального использования (на видео-блоге от первого лица):**
     - Дефолтный стиль изменён на `подробная` (был `краткая`); `краткая` стала чуть
       длиннее - 4-6 предложений вместо 2-4.
     - Промпты явно требуют **сокращать, а не пересказывать своими словами** (раньше
       модель интерпретировала и обобщала, теряя формулировки оригинала) и **сохранять
       лицо повествования** - текст от "я" не должен превращаться в "владелец канала
       решил..."/"автор рассказал..." (было и такое на практике).
     - `подробная` теперь явно просит пройтись по ВСЕМ темам текста, а не только по
       главной - иначе 7B-модель на map-reduce иногда теряла часть тем (например,
       про ЖКХ) просто пропуская их.
     - **Найден и исправлен глитч Qwen2.5**: на длинной генерации модель иногда
       "съезжала" на китайский язык посреди русского ответа. Исправлено явным правилом
       в промпте ("отвечай только на русском") + снижением `temperature` до `0.2`
       (фактическая задача суммаризации не нуждается в высокой температуре/креативности).
     - Добавлены регрессионные тесты: `test_summarize_preserves_first_person_voice`,
       `test_summarize_stays_in_russian_no_language_drift`, `test_summarize_default_style_is_detailed`.
5. **M4 — Склейка CLI** ✅ выполнено
   - `src/localscribe/cli.py` (Typer): команды `process` (полный пайплайн), `transcribe`,
     `summarize` (отдельные шаги), `doctor` (сквозная самопроверка окружения).
   - Консольный скрипт `localscribe` (entry point из `pyproject.toml`) + `python -m localscribe.cli`.
   - `--verbose` для debug-логов (rich), прогресс по шагам (`[1/3]`/`[2/3]`/`[3/3]`).
   - 6 тестов (`tests/test_cli.py`, `typer.testing.CliRunner`) на реальном видео-фикстуре
     (`tests/fixtures/sample_clip.mp4`): полный `process`, `--keep-audio`, раздельные

## 7. Открытые риски / на что обратить внимание
- **Длинные транскрипты**: контекстное окно локальной LLM может не вместить весь текст лекции/подкаста целиком — нужен map-reduce (разбить транскрипт на части → суммаризировать части → суммаризировать суммаризации).
- **VRAM**: 8GB придётся делить между Whisper и LLM, если захочется гонять их параллельно — по умолчанию будем работать последовательно (сначала выгружаем Whisper, потом поднимаем LLM-запрос к Ollama).
- **RTX 5060 (новая архитектура)**: нужно будет проверить, что актуальная версия CUDA-сборки PyTorch/CTranslate2 её поддерживает — это первое, что проверим на шаге M0.
